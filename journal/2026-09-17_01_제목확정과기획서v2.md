## 3. 핵심 프롬프트 (원문)

### 프롬프트 1
```
받을돈으로 잘 진행해 보고싶어 뭐부터 해야 해?
```
**AI 응답 요약:** 중단됐던 기획서 v2 작업을 재시작하고, 작가가 할 일 세 가지(제목 선택, 주최 측 문의, 기획서 v2 검토)를 제시했다.

### 프롬프트 2
```
제목 고르기 부터 하자. 더 후킹, 관객 독자들에게 직관적으로 더 끌릴수 있는 그런 제목으로 더 추천해줘
```
**AI 응답 요약:** 1차 제목이 "보고 나면 뜻이 달라지는" 쪽에 쏠려 포스터 앞에서 약했다고 진단하고, 3초 테스트(감이 오는가 + 궁금해지는가)를 기준으로 2차 후보 20개를 요청했다. 맥스는 1차의 가장 큰 결함을 "제목에 사건이 없었다"로 자기 진단했다.

### 프롬프트 3
```
공모전 취지를 보고 입상 가능성이 높은제목으로 10개 추천해
```
**AI 응답 요약:** 관객 후킹용 제목과 심사위원용 제목이 다를 수 있다는 전제로, 심사 환경(문학 출신 심사위원, A4 기획안 첫 줄, AI 공모전의 밑주제)을 조건으로 추가했다. 결과를 흥행형·입상형·균형형으로 나누게 했다.

### 프롬프트 4
```
균형형 추천 5개로 가자
```
**AI 응답 요약:** 균형형을 중심 결과물로 삼고 5개로 확대했다. 5개마다 포스터 카피, 심사 인상, **이 제목을 골랐을 때 잃는 것**을 붙이고 순위는 매기지 않게 했다.

### 프롬프트 5
```
빚쟁이로 가자
```
**AI 응답 요약:** 제목을 〈빚쟁이〉로 확정하고, 톰에게 동일 제목 사용 이력과 사전 뜻(빌려준 사람/빚진 사람 두 가지) 확인을 맡겼다.

### 프롬프트 6
```
넷플릭스 드라마나 영화 혹은 웹툰으로의 확장전개를 고려했을때 몇안이 좋을까?
```
**AI 응답 요약:** 고문 빅터에게 매체별(극장 영화 / OTT 8부작 / 웹툰) 판정을 요청했다. 빅터의 결론은 "확장 최적안과 영화 최적안은 배타적이지 않다"였고, 영화용으로 쓰되 나중에 스위치만 켜면 확장 버전이 되는 조합(신고 삭제 / 연도별 세로줄 / 함께 모른다 + 15초 스침)을 추천했다.

### 프롬프트 7
```
처음에 이야깃거리 추천했던것 다시 보여줘
```
**AI 응답 요약:** 1차 18개, 2차 17개, 복수 8개를 한자리에 정리해 보여줬다.

### 프롬프트 8
```
빚쟁이말고 다른 이야기로 돌리려 해. 공모전에 뽑힐만한 제목과 이야깃 거리 뽑아줘.심사숙고해줘
```
**AI 응답 요약:** 〈빚쟁이〉를 접고, 이번에는 공모전 심사 기준(완성도 50 / AI 협업 30 / 대중성·확장 20)을 역설계한 발굴을 기획 PD 이선에게 요청했다. 제목을 로그라인과 함께 설계하고, 후보마다 자체 채점과 예상 약점까지 쓰게 했다.
